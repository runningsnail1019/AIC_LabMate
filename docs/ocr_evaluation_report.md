# LabMate 第二项任务 OCR 测试与接入建议

日期：2026-10-12。现有应用基准提交：`c5cd9b3`。

## 结论

现阶段建议暂不把专用 OCR 设为照片分析主流程的必需依赖，继续保留已接入的设备模板与现有 VLM；OCR 可以作为后续可选的读数辅助。这个建议来自现有材料上的本地 OCR 探查及部署取舍，不是“Qwen 比 OCR 更准确”的实验结论。

本次确实运行了 PP-OCRv5 server 和 mobile 两种本地配置，共 32 种输入条件、32 次完整识别调用。OCR 能读出相当一部分关键内容，但仍有等号与减号、单位字符、正号和小字的误识别；裁剪屏幕减少了耗时，但没有普遍提高本轮严格字符串命中成绩。因此不能预先认定“加 OCR 就会更准”。

**尚未完成的关键对照：**本机应用健康接口显示 `qwen_key_configured=false`、`demo_mode=true`，因此现有 Qwen 整图、Qwen 裁屏、Qwen 加 OCR 三组没有实测。没有用模拟返回值填充成绩，也没有用当前助手的图像理解能力冒充仓库里的 Qwen。仅靠这些材料和现有运行条件，无法实证决定专用 OCR 是否优于现有 Qwen，或融合后是否提升最终回答质量。

## 用了哪些现有材料

| 材料 | 区域数 | 用途 |
|---|---:|---|
| 实拍示波器开机照片 | 2 | 检查屏幕是否出现伪数字或伪读数 |
| 实拍信号发生器黑屏照片 | 1 | 检查无显示信息时是否误检 |
| 实拍示波器测量界面 | 1 | 14 个数值及单位关键字符串 |
| SDG2000X 手册屏幕图 | 1 | 6 个数值及单位字符串，另有负载与输出状态 |
| SDM3055X-E 手册单显和双显图 | 2 | 5 个数值及单位字符串，另有测量功能 |
| SDS2000X HD 手册屏幕图 | 1 | 8 个数值及单位字符串 |

合计 4 张实拍、3 张手册页图中的 4 个屏幕区域，共 7 个源图、8 个测试区域；每个区域进行整图及裁屏处理，再分别测两种 OCR 配置。32 个结果不是 32 张独立照片，也不是 32 次仪器实验。实拍中的两张开机画面来自同一台示波器；正常显示读数的实拍只有一张，不能代表所有三类仪器。

万用表单显和双显来自同一个手册页，不能当作两张独立实拍。手册 SDG 图来自 PDF 第 12 页、印刷第 10 页；SDM 来自 PDF 第 19 页、印刷第 7 页；SDS 来自 PDF 第 27 页、印刷第 25 页。使用的是已目视核对的页面图像，不是从 PDF 文本层抽取答案。

实拍 Plus 示波器只用于文字读取探查，没有误套 HD 设备模板。说明书图中有箭头、标记和示例值，与真实实验条件不同，其成绩单独统计。

## 怎么测的

使用 RapidOCR 3.4.1 和 ONNX Runtime 1.31.0 在 Windows 的独立 Python 3.12 环境中执行 PP-OCRv5，CPU 四线程，无 GPU。明确指定 server/server 或 mobile/mobile 的检测与识别模型，而非使用 RapidOCR 默认模型。方向分类使用附带的 PP-OCR 二分类模型。已记录实际加载文件名、模型 SHA256 和软件版本。

整图与裁屏均使用最长边 1800、JPEG quality 84，与当前应用的图片压缩策略一致。裁剪区域来自原始图，在压缩前裁剪；没有透视校正、阈值化、颜色反转、训练微调或 OCR 后纠错。裁剪框为本轮目视标注，**没有因此给 demo 增加自动裁剪功能**。手册“整图”指整张页面，不是整机照片，其额外文字会影响耗时，不能直接推算真实仪器服务延迟。

每种输入完整实测一次。之前试跑曾在首张开机图上重复执行，随后停止；该中止试跑不计入最终 32 次成绩。耗时是本机单次观测，不是稳定的服务延迟或与 Qwen 的端到端速度对比。

参考答案由助手在查看 OCR 输出前直接目视原图建立，并核对对应区域。未由人员独立复核，不能当作正式人工金标准；本轮属于小样本探索测试。

### 评分含义

主指标是对应区域内数值及单位关键字符串的严格命中，共 33 个条目，其中实拍 14 个、手册 19 个。另有 4 个状态条目，记录在明细中，不混入主指标。

允许显示空格和 μs/us 等价形式；保留小数位、正负号、单位前缀大小写、不等号及严格字符边界。同一行被拆成多个文字框时按几何位置重组，不把不同行的数字直接粘在一起。遗漏等号、出现重复减号或丢失显式正号可能计为严格不匹配，即使其中的数字部分正确。

**这个指标不是语义字段提取准确率，也不是整个系统的回答准确率。** 例如 `+1.99931 VAC` 的正号漏读属于原文不完整，不能据此声称其数值已变为负数；`X1--2.500ms` 属于符号上下文不完整，不能直接当作确定的有效测量值。字段所属通道、光标计算与实测频率的语义区别，仍需上层理解和验证。

## 实测结果

| OCR 配置 | 实拍整图 14 项 | 实拍裁屏 14 项 | 手册整页 19 项 | 手册裁屏 19 项 |
|---|---:|---:|---:|---:|
| PP-OCRv5 server | 11/14，78.6% | 9/14，64.3% | 17/19，89.5% | 15/19，78.9% |
| PP-OCRv5 mobile | 9/14，64.3% | 6/14，42.9% | 17/19，89.5% | 13/19，68.4% |

实拍成绩完全来自唯一一张正常显示读数的照片。不能把这些百分比写成“三类仪器的 OCR 总体准确率”，也不能据此给出统计显著性。没有参数搜索或对照组验证，裁屏分数下降的原因未被严格分离；可能与文本检测分组、缩放、符号识别等因素有关。不能得出“所有裁剪都会变差”。

### 具体错误

| 位置 | 参考原文 | 实际 OCR 文本示例 | 影响 |
|---|---|---|---|
| 实拍光标倒数 | `1/ΔX=200.00Hz` | server 裁屏：`1/AX-200.00Hz` | 等号被读成减号，不能直接以简单正则确定数值符号 |
| 同一光标倒数 | `200.00Hz` | mobile 整图：`1/AX-200.00H2` | Hz 的 z 被读成 2，单位不完整 |
| 手册相位设定 | `0.00°` | server 裁屏：`0.00 O` | 度符号变成字母 O，文字框置信度约 0.998 |
| 万用表单显主读数 | `+1.99931 VAC` | server 裁屏：`1.99931 VAC` | 显式正号丢失；数字部分正确，不应夸大为数值反号 |
| 手册采样率 | `2.00GSa/s` | mobile 整页：`2.00GSa/5` | s 被读成 5，采样率单位表达错误 |
| 开机负样本 | 只有品牌，无读数 | mobile 第二张裁屏额外输出 `5` | 图案或局部内容可产生孤立数字误检 |

这些例子表明，OCR 的高分不是经过校准的正确概率，原始文本不能无检查地作为下一步操作依据。

### 负样本与耗时

两种配置、两种输入方式对三个负样本都未检出“数值加单位”的伪读数；但 mobile 在第二张开机图的裁屏输入中误检了一个裸数字 `5`。因此不能声称 OCR 完全没有误识别。程序应结合屏幕状态、字段位置与单位，不把任何数字都当成测量值。

仅列有正常读数的实拍图耗时，避免让三个简单负样本的速度掩盖实际读数成本：

| 配置 | 整张实拍 | 屏幕裁剪 | 本次实际使用的权重大小 |
|---|---:|---:|---:|
| server | 76.91 秒 | 40.85 秒 | 约 165.25 MiB |
| mobile | 1.36 秒 | 0.85 秒 | 约 21.02 MiB |

server 对最后一张手册整页还观测到 204.67 秒，不能据此推断所有 OCR 都很慢。mobile 的本地速度具有辅助模块的可行性，但精度、符号处理及融合效果仍需独立验证。上述调用不含首次模型下载；没有产生收费模型 API 调用，尚未测量部署运维成本及 Qwen 融合的端到端增量。

## 对现有框架的建议

当前不新增必选 OCR 依赖，也不替换 VLM。先保留现有模板和模型路径，这次没有修改它们的运行算法或后端依赖列表。

如果之后要试接，可让 OCR 仅作为可选的屏幕读数证据，携带原始文字、位置框、数值单位、来源和置信度，由现有 VLM 判断其含义。它不能替代设备部件、波形或接线理解；与现场图像或另一结果冲突时应返回不确定、提示复核，而非自动相信分数更高的一方。可以优先试 lightweight 配置，但不能据本轮数据承诺会改善最终回答。

完成真正的接入决策不一定需要再拍照：现有材料可以用于 Qwen 整图、裁屏和融合组的受控试跑；缺少的是可用模型运行配置。三组若仍没有真实输出，报告只能保留“暂不强制接入、优势尚未确定”的建议，不能写成“现有大模型已经足够”或“专用 OCR 更强”。

本次结果保存在本地，没有把 OCR 接入 demo，没有发送实拍照片到云模型，也没有覆盖第一项模板。复制代码到其他电脑不携带 OCR 虚拟环境或模型文件，需按独立实验说明安装。

复现步骤见 [实验说明](../experiments/ocr_evaluation/README.md)。结果数值应以 JSON 和 CSV 为准；不要从 OCR 置信度推算准确率。

## 参考资料如何用于判断

专用 OCR 值得测试的依据来自其文字检测识别能力，而不是“专业模型必然胜出”的假设。PP-OCRv5 论文报告了通用 OCR 基准上的竞争力，但不能直接移植为本项目仪器屏幕的性能结论。[PP-OCRv5 原论文](https://arxiv.org/abs/2603.24373)

本轮按官方说明明确选择 PP-OCRv5 与本地 ONNX 推理，避免默认模型版本混淆。[RapidOCR 使用 PP-OCRv5](https://rapidai.github.io/RapidOCRDocs/main/install_usage/rapidocr/how_to_use_ppocrv5/)

图像细节受输入缩放影响，需要把预处理与识别模型分开研究，不能只比较模型名字。[阿里云视觉理解说明](https://help.aliyun.com/zh/model-studio/vision/)
