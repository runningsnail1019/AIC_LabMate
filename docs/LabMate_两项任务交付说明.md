# LabMate 设备模板与 OCR 研究交付说明

日期：2026年10月12日

项目：AIC_LabMate

交付分支：feat/manual-device-templates

## 工作结论

本阶段完成了两项工作：依据三份仪器说明书设计设备照片分析模板，并接入现有网页和后端；针对是否需要额外 OCR，完成资料调研和现有图片上的本地测试，形成阶段性选型建议。

第一项已完成模板设计与代码接入。第二项已完成调研、初步测试和建议交付。当前建议继续采用“设备模板＋现有视觉语言模型”的主流程，暂不额外接入必选 OCR，保留后续将 OCR 作为读数辅助的可能。

## 第一项 设备照片分析模板

### 设计依据与覆盖范围

模板主要依据老师提供的三份说明书，整理前面板、后面板和屏幕示意图中的部件名称、作用及可观察信息。现场照片用于核对拍摄条件和设备外观；说明书图只作为部件参考，不能当作现场读数或实际接线状态。

| 模板设备 | 部件与分组条目 | 主要整理内容 |
|---|---:|---|
| SDS2000X HD 示波器 | 34 | 显示区、控制区、模拟输入、触发与通信接口、屏幕参数 |
| SDG2000X 信号发生器 | 32 | 显示区、菜单与键盘、旋钮、通道输出、时钟与辅助接口 |
| SDM3055X-E 数字万用表 | 39 | 显示区、测量功能、输入端子、量程与读数、后面板接口 |

合计 105 个部件或分组条目，不代表 105 个独立物理部件。每台设备配置三张手册参考页，共九张，分别覆盖前面板、后面板和屏幕。使用时选择与仪器相符的模板；不要求此次额外扩展 SDS2202X Plus 模板。

### 模板给模型提供什么

模板包含设备标识、部件目录、说明书来源、分区域提示词、结构化观察 JSON 规范和示例。模型需要说明照片中看到了哪些部件、位置和可读信息；对遮挡、模糊、黑屏或不能确定的内容使用 unknown 或 null。

模板明确区分现场照片与手册参考图，要求先分析现场照片，不抄参考图上的示例值。单张照片不能证明波形随时间稳定，也不能仅凭仪器端线缆就认定整个电路连接正确。

## 第一项 接入方式与当前流程

### 用户现在怎样使用

1. 在网页选择设备模板，确认设备型号和照片区域，可选择是否附带说明书参考图。
2. 上传当前仪器照片并提问。后端把现场照片、所选模板的部件说明和相关参考图组织为模型输入。
3. 模型返回现场观察和本轮指导。后端检查模板观察 JSON、部件编号及坐标，并沿用原有检索和安全门控流程。
4. 网页显示指导、视觉观察数据和本轮模板是否实际应用。切换设备时清空旧对话，避免跨设备沿用状态。

与原流程相比，模型现在可以获得明确的设备部件目录与对应面板参考，而不只是接收照片和问题；输出也增加了模板观察的结构检查。这增强了设备针对性和结果可检查性，不等同于已经证明所有识别结果更准确。不选择模板时仍保留原有流程。

### 仓库里增加或修改了什么

- `backend/device_templates/`：新增三套模板、提示词、JSON 规范、目录加载与校验程序、九张手册参考页和来源记录。
- `backend/app/main.py`：接入模板目录接口和分析请求参数，将所选模板加入现有模型调用，并校验返回的结构化观察。
- `frontend/index.html`：增加模板选择、照片区域、参考图开关、模式与应用状态提示。
- `backend/requirements.txt`：增加 jsonschema，用于结构检查。
- `tests/`：增加模板、后端接入和前端交互检查。
- `docs/`：保留原交付说明，补充接入说明、本次 OCR 报告及两项任务综合交付说明。

组长原有知识库、工作流和启动脚本保留。此前网页上传产生的根目录重复文件已归位，原 README 已恢复；本次只在 README 追加交付资料入口。改动继续提交到功能分支，不直接合并 main。

### 当前功能边界

已有模板通过现有 VLM 调用路径使用；本阶段没有增加自动裁屏、YOLO 检测或专用 OCR，也未把三份新手册全文导入原知识库。模板提供部件参考，完整操作指导仍需匹配的知识库证据。实际图像识别沿用项目的有效模型配置。

## 第二项 OCR 调研与本地测试

### 测试材料与方法

使用已有四张现场照片和三张手册页图中的四个屏幕区域，共七个源图、八个测试区域。现场照片包括两张开机画面、一张黑屏和一张正常读数画面；手册图包括信号发生器、万用表单显与双显、示波器界面。

通过 RapidOCR 3.4.1 和 ONNX Runtime 1.31.0，在本机 CPU 上实际运行 PP-OCRv5 server、mobile 两种检测与识别配置。每个区域分别使用整图和人工裁屏输入，合计 32 次完整识别调用。最长边限制为 1800，JPEG 质量为 84，与现有应用压缩策略一致；未进行专门训练、透视校正或识别后纠错。

评分检查 33 个数值及单位关键字符串，其中实拍 14 项、手册 19 项；另记录四个状态条目。严格检查正负号、小数、单位前缀和特殊符号，允许空格及 μs/us 等价形式。参考标注在查看 OCR 结果前目视建立，未经人员独立复核。

### 关键字符串命中结果

| OCR 配置 | 实拍整图 | 实拍裁屏 | 手册整页 | 手册裁屏 |
|---|---:|---:|---:|---:|
| PP-OCRv5 server | 11/14 78.6% | 9/14 64.3% | 17/19 89.5% | 15/19 78.9% |
| PP-OCRv5 mobile | 9/14 64.3% | 6/14 42.9% | 17/19 89.5% | 13/19 68.4% |

以上是本批资料的严格字符串命中，不是系统回答准确率。实拍读数成绩来自一张有效照片；32 次调用不是 32 张独立照片。裁屏在本次减少了耗时，但没有普遍提高严格命中成绩，不能推断所有裁剪都有效或无效。

### 主要发现

OCR 能读出较多仪器参数，但出现了 Hz 读成 H2、度符号读成 O、等号读成减号、显式正号丢失和采样率单位字符错误。一条度符号错误的识别分数约为 0.998，说明高分也不能代替核对。

三个无有效读数的区域均未出现“数值加单位”的伪读数，但 mobile 在一张开机图裁屏中额外识别出裸数字 5，仍需结合屏幕状态和单位过滤。

正常读数实拍中，server 整图和裁屏单次耗时约 76.91 秒、40.85 秒；mobile 约 1.36 秒、0.85 秒。轻量配置具备辅助部署的潜力，server 在本机 CPU 上的成本较高。耗时为单次观测，不是稳定服务延迟。

## 第二项 资料依据与接入建议

### 查阅资料支持什么判断

PaddleOCR 官方文档将通用 OCR 流程分为文字检测、识别及可选预处理模块，输出识别文字、位置和分数，并区分 server 与 mobile 的部署取舍。这说明 OCR 可以提供局部文字证据，但其通用基准成绩不能直接当作本项目仪器屏幕准确率。[1]

RapidOCR 官方说明提供了明确选择 PP-OCRv5 的配置方法。本次明确记录实际加载的模型文件、版本和哈希，避免把默认模型与实际测试模型混淆。[2]

Qwen2.5-VL 技术报告介绍了目标定位、图表理解与结构化信息提取能力，支持由视觉语言模型承担整体理解的设计方向。该论文型号不直接等同于仓库的 qwen-vl-plus，不能照搬论文成绩。[3] 阿里云视觉理解说明还表明图像预处理和缩放会影响输入细节，应把图像质量与模型能力分开考虑。[4]

### 当前阶段的决定

继续保留“设备模板＋现有 VLM”主流程，暂不额外接入必选 OCR。依据是本次测试中专用 OCR 仍有关键符号和单位错误，额外部署有速度与维护成本，而它不能单独承担设备部件、参数含义与用户问题的整体理解。

如后续发现关键读数反复识别错误，可针对这些字段试用轻量 OCR。保留原始文字、位置框和来源，把 OCR 结果作为辅助证据；发生冲突时提示复核，不自动采用分数较高的一方。

本建议属于小样本测试与资料调研形成的阶段性选型，尚未通过现有 Qwen 与 OCR 的同图对照验证，不能表述为“大模型已被证明更准确”。
